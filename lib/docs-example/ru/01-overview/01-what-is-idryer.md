# Что такое iDryer и зачем эта библиотека

!!! note "Перед чтением"
    Термины этой документации — в [04-glossary.md](04-glossary.md). Держите вкладку открытой, некоторые понятия вводятся постепенно, полные определения всегда там.

## Продукт iDryer

**iDryer** — это система для сушки филамента 3D-печати. Физически это шкаф с одной или несколькими камерами. В каждой камере — нагреватель, вентилятор, датчики температуры и влажности, опционально тензодатчики (весы катушки) и RFID-ридеры (идентификация катушки).

Пользователь управляет сушкой:

- локально, через экран и меню на устройстве,
- удалённо, через приложение или веб-портал [portal.idryer.org](https://portal.idryer.org).

Под капотом:

- **Контроллер** (MCU — MicroController Unit, микроконтроллер сушилки) управляет «железом»: считывает датчики, регулирует нагрев PID-ом, ведёт экран и меню, хранит настройки в EEPROM.
- **Сетевой модуль** (LINK — имя собственное, а не аббревиатура) даёт устройству WiFi, подключается к облаку iDryer, принимает команды с сервера, публикует телеметрию.
- **Облако** (portal + MQTT-брокер + backend) — общая инфраструктура для всех устройств iDryer.

## Зачем эта библиотека

**`idryer-protocol`** — это библиотека на C++, которая закрывает всё, что связано со связью:

- **UART-протокол** между контроллером и сетевым модулем (бинарные кадры, CRC, ACK/retry).
- **MQTT-клиент** для сетевого модуля (подключение к брокеру, публикация телеметрии, приём команд).
- **HTTP-клиент** для привязки устройства к аккаунту пользователя через публичный API портала.
- **Парсер команд** с облака и нормализация их в UART-пакеты.

Библиотека предназначена для **разработчика, который делает своё устройство, совместимое с облаком iDryer**.

## Кому адресована библиотека

Три типовые траектории:

| Вы делаете | Что используете из библиотеки |
|------------|--------------------------------|
| Свой контроллер (своя плата, STM32 / RP2040 / ESP32 / другое) | Только UART-протокол. С облаком работает **готовый** сетевой модуль. |
| Свой сетевой модуль на ESP32 | MQTT + HTTP + UART-мост. Контроллер — ваш или сторонний. |
| Standalone устройство (один ESP32 за всё) | Всё: UART-структуры (нативно), MQTT, HTTP, парсер команд. |

**Не предназначено** для:

- разработки своего портала или своего MQTT-брокера,
- замены приложения для обычного пользователя.

Если цель — полностью автономная экосистема, без облака iDryer, то эта библиотека не нужна. Возьмите её UART-раздел как пример формата и пишите своё.

## Границы ответственности

Библиотека **не делает** следующее — это задача прикладной прошивки:

- PID-регулирование нагрева, управление датчиками, логика сушки.
- Экран, меню, ввод с энкодера/кнопок.
- Хранение пользовательских настроек в EEPROM.
- Решение, **когда** публиковать в MQTT (библиотека даёт API, частоту задаёт прикладной код).
- Автоматическая публикация `Log` из UART в MQTT `events` — это делается только если прикладной код зарегистрирует соответствующий колбэк. Подробнее, почему так, — в [03-nodes-and-roles.md](03-nodes-and-roles.md).

Библиотека **делает**:

- Упаковка/распаковка UART-кадров с CRC и ACK.
- Подключение к WiFi, HTTP-вызовы к порталу iDryer, MQTT-клиент.
- Публикация телеметрии/статуса/весов/RFID в стандартные топики iDryer.
- Разбор MQTT-команд (`drying`, `stop`, `profile`, …) и преобразование их в UART-пакеты для контроллера.

## Архитектура в одной картинке

```
┌──────────────────┐   UART    ┌──────────────────┐   MQTT (TLS)   ┌──────────────────┐
│   Controller     │◄─────────►│  Network module  │◄──────────────►│   iDryer cloud   │
│                  │           │                  │                │                  │
│  • PID / heater  │           │  • WiFi          │                │  • portal API    │
│  • sensors       │           │  • MQTT client   │                │  • MQTT broker   │
│  • screen / menu │           │  • HTTP client   │                │  • web + app UI  │
│  • EEPROM        │           │  • claiming flow │                │                  │
└──────────────────┘           └──────────────────┘                └──────────────────┘
       (ваш код)                  (библиотека)                         (готовое)
```

В документации этот контроллер называется **MCU**, сетевой модуль — **LINK**, облако — **portal** или **backend**. Полный список терминов: [04-glossary.md](04-glossary.md).
