# TRANSLATION_GUIDE — инструкция для Codex (и любого ИИ-переводчика)

Документ описывает, **как перевести русскую документацию `idryer-protocol` на английский** без потери структуры, семантики и технических инвариантов.

> **Направление перевода: `docs/ru/` → `docs/en/`.**
> `ru/` — это **канонический источник**, его **запрещено** редактировать в ходе перевода.
> `en/` на момент запуска — клон `ru/` с warning-блоком «Translation in progress» в `README.md` и вставками англоязычного текста только в README. Остальные файлы `en/*.md` фактически идентичны `ru/*.md` и подлежат полному переводу.

---

## 1. Цель и результат

- На выходе **все файлы в `docs/en/`** должны быть полностью на английском, за исключением элементов из раздела [§6 «Что НЕ переводить»](#6-что-не-переводить).
- Структура каталогов, имена файлов, число строк, число code-fence блоков, число admonition-блоков, число столбцов таблиц — **сохраняются один-в-один**.
- Смысл каждого абзаца сохраняется. Английский текст не вольный пересказ, а точный эквивалент.
- Стиль — технический, нейтральный, императивный (эталон — [Klipper docs](https://www.klipper3d.org/) и [Voron docs](https://docs.vorondesign.com/)).

---

## 2. Порядок работы (оркестратор)

Работу ведёт **оркестратор** (главный агент). Он:

1. Читает этот документ целиком.
2. **Переводит `docs/en/01-overview/04-glossary.md` в первую очередь, самостоятельно, не делегируя.** Этот файл — источник авторитетных английских терминов для остальных глав.
3. Формирует **словарь переводов** (`TRANSLATION_GLOSSARY.md`, см. [§5](#5-глоссарий-терминов)) на основе переведённого 04-glossary.md.
4. Запускает **субагентов параллельно** — по одному на каждую директорию верхнего уровня (см. [§3](#3-разделение-на-субагенты)).
5. После завершения всех субагентов — прогоняет **финальные проверки** ([§8](#8-финальные-проверки)).
6. Удаляет warning-блок «Translation in progress» в `docs/en/README.md` и переводит английский заголовок (он уже есть) + переводит русскую часть.

---

## 3. Разделение на субагенты

### 3.1 Критерии, когда привлекать субагента

Субагент запускается **на каждую директорию верхнего уровня** из списка:

| Субагент | Пакет файлов | Примерный объём |
|----------|--------------|------------------|
| `translator-01-overview`        | `docs/en/01-overview/*.md`        | 6 файлов, ~1180 строк |
| `translator-02-getting-started` | `docs/en/02-getting-started/*.md` | 6 файлов, ~1620 строк |
| `translator-03-uart`            | `docs/en/03-uart/*.md`            | 7 файлов, ~1460 строк |
| `translator-04-mqtt`            | `docs/en/04-mqtt/*.md`            | 6 файлов, ~1180 строк |
| `translator-05-cloud`           | `docs/en/05-cloud/*.md`           | 4 файла, ~650 строк |
| `translator-06-flows`           | `docs/en/06-flows/*.md`           | 5 файлов, ~880 строк |
| `translator-07-features`        | `docs/en/07-features/*.md`        | 8 файлов, ~2060 строк |
| `translator-readme`             | `docs/en/README.md`               | 1 файл, ~210 строк |

**04-glossary.md переводится оркестратором ДО запуска субагентов** — он не входит в пакет `translator-01-overview`. Субагент `translator-01-overview` работает со всеми остальными файлами `01-overview/`.

### 3.2 Когда **не** использовать субагента

- Правка одиночного файла после финальной проверки.
- Уточнение термина по глоссарию.
- Снятие warning-блока в README.
- Любая работа < 100 строк текста.

### 3.3 Передача контекста субагенту

Каждому субагенту передаётся **самодостаточный промпт**, включающий:

- Ссылку на этот `TRANSLATION_GUIDE.md` (полный путь).
- Ссылку на `TRANSLATION_GLOSSARY.md` (созданный оркестратором, см. [§5](#5-глоссарий-терминов)).
- **Абсолютные пути** к файлам-источникам в `docs/ru/<dir>/` и файлам-целям в `docs/en/<dir>/`.
- Напоминание: **источник не редактировать**, редактируется только `docs/en/`.
- Требование вернуть краткий отчёт: какие файлы переведены, какие термины встретились и не нашлись в глоссарии.

### 3.4 Параллелизм

Все 8 субагентов запускаются в **одном batch-запросе** (параллельно). Зависимости между ними нет — файлы не ссылаются друг на друга по содержимому, только по именам (а имена не меняются).

## 4. Критерии перевода

### 4.1 Точность

- Каждое предложение источника имеет эквивалент в целевом файле. Ничего не выбрасывается, ничего не добавляется.
- Числовые значения, идентификаторы, команды, таймауты — переносятся **буквально**.
- Если в источнике указан конкретный код ошибки (`CRC_FAIL`, `0x42`, `QoS 1`) — он остаётся как есть.

### 4.2 Стиль английского

- **Registers**: technical documentation, neutral, imperative. Present tense. American English spelling (`behavior`, not `behaviour`).
- **Обращение к читателю**: `you`, прямые императивы: *«Verify that…»*, *«Connect the device…»*, *«Make sure…»*.
- **Запрет**: маркетинговые прилагательные (`powerful`, `modern`, `simple`, `just`, `easy`), восклицания, эмодзи, призывы к действию вне процедур.
- Абзацы короткие (1–4 предложения). Одна мысль — один абзац.
- Термин вводится при первом появлении, далее — без повторной расшифровки.

### 4.3 Структура Markdown

Сохраняется **побитово**:

- Количество и уровень заголовков (`#`, `##`, `###`).
- Порядок и тип списков (маркированные / нумерованные).
- Все admonition-блоки MkDocs Material: `!!! note`, `!!! warning`, `!!! danger`, `!!! tip`, `!!! info` — тип блока **не меняется**, переводится только заголовок (в кавычках) и тело.
- Таблицы: число столбцов, разделители `|`, выравнивание `:---:` — без изменений.
- Code fences (```` ``` ````): число, язык после открывающего ``` (`bash`, `cpp`, `json`, `yaml`) — без изменений.
- Пустые строки между блоками — без изменений.

### 4.4 Ссылки

- Внутренние относительные ссылки на `.md` файлы: **не трогать**. Пути сохраняются 1-в-1: `[link](../06-flows/03-remote-config.md)` остаётся таким же. Структура `en/` зеркалит `ru/`, поэтому путь валиден.
- Якоря на заголовки (`#some-anchor`): если ссылка указывает на заголовок **внутри того же файла или любого другого файла, подлежащего переводу** — якорь **меняется** на новый, соответствующий переведённому заголовку. Оркестратор после завершения всех субагентов **проверяет все якоря** (см. [§8.3](#83-проверка-якорей)).
- Внешние URL (`https://…`) — не меняются.
- Текст ссылки (`[текст](url)`) — переводится.

### 4.5 Неразрывность с кодовой базой

- Имена C/C++ идентификаторов (`DeviceType::Dryer`, `idryer::uart::Frame`, `onHelloReceived`) — **не переводятся**.
- MQTT-топики (`devices/{deviceId}/telemetry`, `commands/drying`) — **не переводятся**.
- Ключи JSON и полей (`"temp"`, `"humidity"`, `"deviceId"`) — **не переводятся**.
- Имена регистров, пинов (`GP0`, `UART0`, `I2C1`) — **не переводятся**.
- Названия продуктов/брендов: `iDryer`, `iHeater`, `LINK`, `MCU`, `Bambu Lab`, `Home Assistant`, `Moonraker`, `Klipper`, `Mosquitto`, `EEPROM`, `NVS`, `RP2040`, `ESP32`, `STM32` — **не переводятся**.

## 5. Глоссарий терминов

Оркестратор после перевода `04-glossary.md` создаёт файл `docs/TRANSLATION_GLOSSARY.md` в формате:

```markdown
# Translation glossary (ru → en)

| Русский термин | English equivalent | Примечание |
|----------------|--------------------|------------|
| сетевой модуль | network module (LINK) | LINK — имя собственное, не аббревиатура |
| контроллер | controller (MCU) | Сокращение MCU используется как синоним |
| сушилка | dryer |  |
| привязка устройства | device claiming | Не «binding», устоявшийся термин — claiming |
| …              | …                  |            |
```

Субагент **обязан** свериться с этим файлом перед тем, как перевести любой термин. Если термина нет — применяет [§6–§7](#6-что-не-переводить) и добавляет новую пару в возвращаемый отчёт; оркестратор обновляет глоссарий и, при необходимости, делает второй проход.

## 6. Что НЕ переводить

| Категория | Пример | Действие |
|-----------|--------|----------|
| Блоки кода ```` ``` ```` | `bash`, `cpp`, `json`, `yaml` | Оставить как есть, **включая русские строковые литералы внутри**, если они намеренные (они почти всегда — нет, но см. §6.1) |
| Inline code `` ` ` `` | `` `Frame::checksum` ``, `` `devices/{deviceId}` `` | Не трогать |
| Имена файлов | `01-what-is-idryer.md`, `src/main.cpp` | Не трогать |
| Пути | `lib/idryer-protocol/src/` | Не трогать |
| URL | `https://portal.idryer.org` | Не трогать |
| Бренды и продукты | `iDryer`, `iHeater`, `LINK`, `Bambu Lab`, `Home Assistant`, `Moonraker`, `Klipper`, `Mosquitto`, `MkDocs` | Не трогать |
| Идентификаторы и сокращения | `MCU`, `LWT`, `QoS`, `CRC`, `ACK`, `PID`, `NVS`, `EEPROM`, `UART`, `MQTT`, `HTTP`, `RFID` | Не трогать (но при первом упоминании можно развернуть: *MCU (microcontroller unit)*) |
| Нумерация, hex-литералы | `0x44`, `0xAA55`, `115200`, `3.3V` | Не трогать |
| Железные обозначения | `BAT85`, `M3x8 SHCS`, `GP0`, `SPI1` | Не трогать |
| YAML/TOML frontmatter | `---\ntitle: …\n---` | Переводить только текстовые значения; ключи — не трогать |
| HTML-комментарии `<!-- -->` | любые | Переводить текст внутри, тег не трогать |

### 6.1 Частный случай: русские строки внутри кода

Если в code-fence есть **пользовательский текст** (например, `echo "Привет"` или строковый литерал для логов, не являющийся частью протокола) — переводить на английский, **если это пример вывода/ввода для пользователя**. Если это протокольный литерал (идентификатор, значение enum, ключ JSON) — не трогать.

**Сомнения разрешать в пользу «не трогать»** и отмечать в отчёте субагента.

## 7. Что переводить

- Текст параграфов.
- Заголовки всех уровней.
- Ячейки таблиц, кроме колонок с идентификаторами/кодом.
- Заголовки admonition-блоков (в кавычках после типа).
- Alt-text изображений `![alt](path)` — переводить `alt`.
- **Комментарии в коде** — переводить, если комментарий описательный. Если комментарий — метка типа `// TODO`, `// FIXME`, `// SPDX-...` — не трогать.
- Заголовок `# Документация …` и warning-блок «Translation in progress» в `en/README.md` — **удалить** warning-блок целиком (оркестратором, после проверок), а русский заголовок — заменить на английский эквивалент.

## 8. Финальные проверки (оркестратор)

Каждая проверка — автоматизируемая. Если хотя бы одна падает — исправлять и прогонять повторно.

### 8.1 Инвариант числа строк

Для каждой пары `ru/X.md` ↔ `en/X.md` число строк должно совпадать с точностью до ±3 (на случай переноса длинных строк). Отличие `README.md` — ожидается (удалён warning-блок).

```bash
for f in $(find docs/ru -type f -name "*.md"); do
  en="${f/\/ru\//\/en\/}"
  ru_l=$(wc -l < "$f"); en_l=$(wc -l < "$en")
  [ "$ru_l" != "$en_l" ] && echo "DIFF  $f  ru=$ru_l  en=$en_l"
done
```

### 8.2 Инвариант code-fence

Число ```` ``` ```` в файле должно быть чётным и совпадать с источником.

```bash
for f in $(find docs/en -type f -name "*.md"); do
  n=$(grep -c '^```' "$f")
  [ $((n % 2)) -ne 0 ] && echo "ODD fences: $f ($n)"
done
```

### 8.3 Проверка якорей

Для каждой внутренней ссылки вида `[текст](path#anchor)` убедиться, что `path` существует и в файле `path` есть заголовок, порождающий `anchor` (MkDocs использует slugify с `-` и нижним регистром).

### 8.4 Отсутствие кириллицы вне code-fence

После перевода доля кириллических символов **вне code-fence** в каждом файле `en/*.md` должна быть **< 0.01**. Сейчас она 0.45–0.89.

```bash
python3 - <<'PY'
import re, glob
for f in sorted(glob.glob('docs/en/**/*.md', recursive=True) + glob.glob('docs/en/*.md')):
    t = open(f).read()
    t = re.sub(r'```[\s\S]*?```', '', t)
    t = re.sub(r'`[^`]*`', '', t)
    cyr = len(re.findall(r'[а-яА-ЯёЁ]', t))
    lat = len(re.findall(r'[a-zA-Z]', t))
    total = cyr + lat
    ratio = cyr / total if total else 0
    if ratio > 0.01:
        print(f'{ratio:.2f}  {f}')
PY
```

### 8.5 Инвариант таблиц

Число строк вида `|...|...` и разделителей `|---|` должно совпадать с источником.

### 8.6 Инвариант admonitions

Число строк, начинающихся с `!!! `, должно совпадать с источником.

## 9. Критерии качества (что оркестратор проверяет помимо §8)

- **Терминологическая согласованность**: одинаковые термины переведены одинаково во всех файлах. Оркестратор выбирает 5–10 ключевых терминов из глоссария и проверяет через grep по `en/`.
- **Отсутствие буквализмов**: плохо — «At the moment of first launch the device…»; хорошо — «On first boot, the device…». Если субагент оставил кальку — оркестратор корректирует.
- **Идиоматичность**: читабельно для носителя. Не обязано быть идеально — обязано быть понятно и технически точно.
- **Единообразие регистра**: `UART Frame` vs `UART frame` — выбрать один стиль (рекомендуется sentence case для заголовков, кроме признанных имён собственных).
- **Нет «переведённых» команд**: `mosquitto_pub` остаётся `mosquitto_pub`, а не `мосkitto_pub` / `mqtt_publish`. Это относится ко всему, что можно скопировать и выполнить.

## 10. Запреты

- ❌ Редактировать `docs/ru/`.
- ❌ Создавать новые файлы в `docs/en/` сверх существующих.
- ❌ Удалять существующие файлы в `docs/en/`.
- ❌ Переносить/переименовывать директории.
- ❌ «Улучшать» структуру документа по дороге (добавить TOC, убрать раздел, переставить пункты).
- ❌ Вставлять AI-плейсхолдеры вида *«[insert description here]»* в случае неуверенности — если термин неясен, субагент пишет осторожный вариант и **обязательно** упоминает его в отчёте.
- ❌ Использовать `--no-verify`, обходы хуков, форс-пуши.
- ❌ Коммитить и пушить автоматически — финальный коммит и PR делает человек после ревью.

## 11. Формат отчёта субагента

Каждый субагент возвращает:

```
## Отчёт: translator-<dir>

Переведены:
- docs/en/<dir>/01-foo.md
- docs/en/<dir>/02-bar.md

Новые термины, добавленные в предложение для глоссария:
- «флэш-память прошивки» → firmware flash

Сомнения (оркестратор — принять решение):
- В 03-uart/04-binary-structures.md строка 142: строковый литерал «ошибка CRC» внутри C++ кода — оставил как есть, но это может быть пользовательский вывод.

Проверки пройдены: §8.1 ✓, §8.2 ✓, §8.4 ✓ (0.00).
```

Оркестратор агрегирует отчёты, обновляет глоссарий, закрывает сомнения, прогоняет §8 повторно.

## 12. После перевода

- Удалить warning-блок «Translation in progress» в `docs/en/README.md`.
- Не трогать `docs/ru/README.md`.
- **Не коммитить автоматически.** Вывести список изменённых файлов и передать управление человеку.
- Не создавать `TRANSLATION_GLOSSARY.md` в git (добавить в `.gitignore` подмодуля `lib/idryer-protocol/` или положить вне репо).
