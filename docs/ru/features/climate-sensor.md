# Климатический датчик SHT31

Вторая продуктовая задача `Storage Link` — показывать температуру и влажность, если на плате установлен SHT31.

Исходный код:

- [`src/storage/sensors/Sht31ClimateSensor.cpp`](../../../src/storage/sensors/Sht31ClimateSensor.cpp)
- [`src/storage/telemetry/StorageTelemetryPublisher.cpp`](../../../src/storage/telemetry/StorageTelemetryPublisher.cpp)

## Поведение на старте

После `Wire.begin()` устройство:

1. пробует адрес `0x44`;
2. если не отвечает, пробует `0x45`;
3. если оба адреса не отвечают, работает дальше без датчика.

Это не ошибка загрузки продукта.
Флаг `s_sensorOk` просто остаётся `false`, и цикл публикации климата не запускается.

## Частоты работы

- опрос датчика: раз в `1000 ms`;
- публикация телеметрии: раз в `10000 ms`.

Чтение неблокирующее: используется пара `requestData()` / `readData()`, поэтому датчик не тормозит основной цикл.

## Какие данные считаются валидными

Измерение публикуется только если:

- `temperature` не `NaN` и находится в диапазоне `-40..125 C`;
- `humidity` не `NaN` и находится в диапазоне `0..100 %RH`.

Если проверка не проходит, измерение помечается ошибкой и в `telemetry` не уходит.

## Формат телеметрии

Топик MQTT: `idryer/<serial>/telemetry`

LAN WebSocket: сообщение `type = "telemetry"`

Payload:

```json
{
  "units": [
    {
      "unitId": "U1",
      "temperature": 23.5,
      "humidity": 47.2
    }
  ]
}
```

Особенности:

- формат совместим с существующим `units[]` контрактом платформы;
- `temperature` и `humidity` сериализуются с одной цифрой после запятой;
- `pressure` в продукте пока не используется, хотя поле зарезервировано в `SensorReading`.

## Что должен учитывать frontend

- отсутствие `telemetry` не всегда означает offline;
- это может значить, что датчик физически не установлен или не найден на старте;
- если нужны климатические виджеты, они должны быть условными и показываться только при фактическом появлении `temperature`/`humidity`.
