# Подсветка катушки и управление лентой

Главная задача продукта — принять внешнюю команду и подсветить нужную позицию на LED-ленте.
В терминах кода это реализовано в [`LedStripExecutor`](../../../src/storage/led_strip/led_strip_executor.cpp).

## Как это работает

- Лента инициализируется один раз в `setup()` через FastLED.
- Размер буфера задаётся compile-time флагом `STORAGE_MAX_LEDS`.
- Рабочее количество светодиодов берётся из меню `led_count`.
- Активным может быть только один светодиод.

Когда приходит `led.pulse`, устройство:

1. Проверяет `ledIndex` на попадание в диапазон `0..led_count-1`.
2. Гасит ранее активный светодиод, если он был.
3. Включает новый светодиод выбранным цветом.
4. Запоминает `offAt = millis() + durationSec * 1000`.
5. В `loop()` автоматически гасит светодиод по таймеру.

## Почему это соответствует продуктовой задаче

Для портала или локального приложения не нужен сложный эффект или логика по катушкам внутри прошивки.
Прошивка решает более узкую задачу:

- внешний слой знает, какую катушку нужно выделить;
- внешний слой переводит её в `ledIndex`;
- устройство подсвечивает нужную позицию на физической ленте.

То есть знание о складе, ячейках и катушках живёт не в прошивке, а в вызывающем приложении.
Прошивка даёт предсказуемый actuator: "подсвети светодиод N цветом C на T секунд".

## Поддерживаемые типы ленты

В коде поддержаны два физических типа:

- `WS2812B`
- `APA102`

Выбор хранится в меню как exclusive toggle group.
Смена типа ленты сохраняется сразу, но требует reboot, потому что `FastLED.addLeds<>()` вызывается только при старте.

## Порядок цветов

Поддерживаются варианты:

- `GRB`
- `RGB`
- `BRG`
- `BGR`

Это тоже exclusive toggle group.
Если в NVS оказалось повреждённое состояние группы, `LedStripProfile::normalizeGroups()` на старте возвращает конфигурацию к каноническому значению:

- тип ленты по умолчанию — `WS2812B`
- порядок цветов по умолчанию — `GRB`

## Ограничение по току

Пункт меню `psu_ma` сразу вызывает:

```cpp
FastLED.setMaxPowerInVoltsAndMilliamps(5, maxCurrentMa);
```

Это не меняет протокол управления, но влияет на физическую яркость и безопасную нагрузку на БП.

## Текущее ограничение версии

Маршрут `led.animation` уже существует в MQTT и WS, но продуктовая анимация ещё не реализована.
Если приложению нужен не pulse, а последовательность эффектов, это пока надо решать серией `led.pulse` команд либо доработкой прошивки.
