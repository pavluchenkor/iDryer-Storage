# Storage Link — обзор продукта

## Что это за продукт

`Storage Link` в этом репозитории — прошивка ESP32 для адресной LED-ленты и опционального климатического датчика.
Устройство подключается к Wi-Fi, проходит claim через облако iDryer и дальше решает две продуктовые задачи:

- принимает команду подсветки конкретного светодиода, чтобы выделить нужную катушку или ячейку;
- публикует температуру и влажность в `telemetry`, если на I2C найден SHT31.

Это важно: текущий `Storage Link` не управляет нагревом, не работает через RJ45/UART и не содержит продуктовой логики `iHeater`, `Bambu` или `Moonraker`.

## Где находится продуктовый код

- [`src/main.cpp`](../../../src/main.cpp) — composition root устройства: Wi-Fi, cloud, local access, LED strip, SHT31.
- [`src/storage/led_strip/`](../../../src/storage/led_strip) — продуктовая логика подсветки и конфигурации ленты.
- [`src/storage/sensors/`](../../../src/storage/sensors) — работа с SHT31.
- [`src/storage/telemetry/`](../../../src/storage/telemetry) — публикация температуры/влажности.
- [`platformio.ini`](../../../platformio.ini) — env-ы, MQTT endpoints, пины плат.

## Что происходит при загрузке

`src/main.cpp` поднимает устройство сверху вниз:

1. Загружает конфиг ленты из NVS через `lib/idryer-menu`.
2. Инициализирует FastLED под выбранный тип ленты и порядок цветов.
3. Применяет ограничение по току БП.
4. Поднимает I2C и пытается найти SHT31 по `0x44`, затем по `0x45`.
5. Запускает Improv Wi-Fi provisioning через Serial.
6. Поднимает claim/cloud стек из `idryer-core`.
7. Запускает локальный WebSocket на порту `81`.
8. В основном цикле обслуживает cloud, local access, таймер подсветки и телеметрию датчика.

## Внешнее поведение продукта

### Подсветка

- Внешний клиент вызывает `commands/invoke` с `action = "led.pulse"`.
- Продукт включает ровно один светодиод на заданное время.
- Новая команда гасит предыдущий активный светодиод и включает новый.
- `durationSec = 0` выключает текущую подсветку.

### Климат

- Если SHT31 найден на старте, устройство начинает опрашивать его раз в `1000 ms`.
- Валидные данные публикуются раз в `10000 ms`.
- Если датчик не найден, устройство продолжает работать штатно, но `telemetry` по климату не отправляет.

## Граница между продуктом и библиотекой

`lib/idryer-core` здесь не является описанием продукта.
Библиотека даёт инфраструктуру:

- Wi-Fi credentials и device identity;
- HTTP claim flow;
- MQTT client и подписку на `commands/#`;
- LAN WebSocket transport;
- runtime, который сводит cloud и продуктовые обработчики.

Сам продукт описывается кодом в `src/storage` и `src/main.cpp`.
Если вопрос про пины, конфиг ленты, `led.pulse`, SHT31 или частоту публикации, источник истины находится в репозитории продукта, а не в библиотеке.
